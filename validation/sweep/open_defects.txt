# validation/sweep/open_defects.txt
#
# The absolute gate (scripts/sweep_accuracy --ulp --register <this file>) says
# "no point above its derived bound". These points ARE above it. They are open
# defects in the library, not slack in the derivation, and they are carried here
# in full rather than absorbed by loosening a tolerance.
#
# Format: <backend> <kind> <op> <point>.  Checked in BOTH directions:
#   a point above bound that is not listed here     -> gate FAILS (new defect)
#   a point listed here that is no longer above it  -> gate FAILS (register rotted)
# So the file can only shrink. Delete lines as fixes land; never add one without
# understanding what it is.
#
# WHAT IS IN HERE (grouped by mechanism, all complex):
#
#  c log / c log10 / c pow, 82 points x 4 backends = 984
#      Branch cut. On the negative real axis the measured error is exactly
#      2*2^p ulps, i.e. the answer is the correct magnitude with the imaginary
#      part negated: the library and the __complex128 oracle disagree on the
#      sign of zero entering atan2, so one returns +i*pi and the other -i*pi.
#      A convention disagreement, but it is the library's convention that is
#      wrong against C99 Annex G.
#
#  c atanh, 16 points x 3 backends = 48
#      The |z| = 1 pole, approached from grid points 1+1e-8 and 1+1e-9. kappa is
#      5e6..5e7 there and the bound tracks it, but the measured error runs
#      1e5..1e6 times higher still.
#
#  c div, 3..5 points x 3 backends = 11
#      QF/TF/FF complex division where an operand sits at the FP32 subnormal
#      boundary. q = |b|^2 and the scaled bilinear products are modelled as
#      intermediates and are in range; the excess is above what the format
#      explains.
#
#  c tan, 4 points, FF only
#      Pole proximity at FP32 working precision.
#
# Counts by cell are printed by the gate itself; the grouping above is the
# diagnosis, and the per-mechanism history is in docs/history/KNOWN_ISSUES.md.
#
